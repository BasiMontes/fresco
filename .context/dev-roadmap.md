## 6. Live status — query it, never freeze it

Status is volatile — a pasted table here would be stale within days and actively mislead. Query it live instead.

```
bun run jira:sync-issues pull
```
Then read `.context/PBI/epic-tree.md` and the per-story `story.md` files under `.context/PBI/epics/`.

**Recipe B — one-shot live query (ranked, active board):**
```
acli jira workitem search --jql "project = FRESCO AND issuetype in (Epic, Historia) ORDER BY Rank ASC" --paginate --json
```

**Decision rule for "what to work next"**: the highest-ranked story whose §3 blocker(s) are Done in the tracker AND whose §5 mockup gate (if any) is cleared AND whose §6 pre-dev blockers below are resolved. Query live status via `[ISSUE_TRACKER_TOOL]` rather than trusting a point-in-time claim here — this line intentionally does not freeze "what's unblocked right now" (see §1 authority split above; a prior version of this line went stale within the same day it was written).

**Solo-project note**: this repo has no separate QA actor — the developer and the product owner are the same person. A story reaching a code-reviewed, automated-tested state with no live end-to-end walk possible is a legitimate reason to transition it to Done manually rather than leaving Execution Sprints permanently stalled behind a QA step nobody distinct is performing.
