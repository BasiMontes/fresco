Legend: `A ──> B` hard gate (B cannot start until A is Done). No soft (`··>`) edges and no mockup gates (`🔒`) exist in this graph yet.

| FRESCO-7 (Menu Generation) | FRESCO-11 (Calendario \| Reordenar el menú generado arrastrando platos entre espacios) | hard (`Blocks`) | Reordering operates on `meal_plan_recipes` rows that only exist once a menu has been generated and persisted — there is nothing to reorder until FRESCO-7's read/persist path is real (`master-implementation-plan.md` §4 Master Sprint 1). Cross-referenced in FRESCO-11's Out-of-Scope field (does not reimplement generation). |
| FRESCO-7 (Menu Generation) | FRESCO-13 (Lista de la Compra \| Generar y marcar como comprados los ingredientes del menú semanal) | hard (`Blocks`) | Shopping-list consolidation reads all 21 slots' recipes from a persisted `meal_plan_id` — no plan, no list. Cross-referenced in FRESCO-13's Out-of-Scope field. |
| FRESCO-7 (Menu Generation) | FRESCO-15 (Aprendizaje \| Marcar un plato del menú como cocinado o descartado) | hard (`Blocks`) | The cooked/discarded toggle marks a `meal_plan_recipes` slot's `estado` — no persisted plan, no slot to mark. Cross-referenced in FRESCO-15's Out-of-Scope field. |

**Link-type note**: the canonical `{{jira.link_types.dependencies}}` ("Dependencies") type does not exist in this workspace (`bun run jira:sync-link-types` confirms `dependencies → missing, fallback "relates" available`). All five edges above use the workspace's `Blocks` type instead, per `.agents/jira-required.yaml`'s own declaration that `blocks` is "a Jira built-in synonym of `dependencies`... treated equivalently by sprint-sequencing" — not a lossy degradation to `relates`. Direction was verified post-creation via `acli jira workitem link list --key <KEY> --json` on every issue on both sides of each edge (not just the CLI's own confirmation message, which — empirically, for `Blocks` in this workspace — turned out to be the direct, non-inverted reading: `--out X --in Y --type Blocks` really does produce "X Blocks Y"; the `acli` skill's documented `--out`/`--in` inversion gotcha did NOT reproduce for the `Blocks` link type here and was reconciled by deleting and recreating one link with swapped arguments before all three new edges were created — see `.session/product-management/master-sprint-1/progress.md`).

**No edges exist among FRESCO-11 / FRESCO-13 / FRESCO-15 themselves** — `master-implementation-plan.md` §4 explicitly frames Editable Calendar, Shopping List, and the Learning Toggle's recording capability as independent extensions of the same upstream table, none blocking the others (mirrors the FRESCO-5/FRESCO-9 parallel precedent in Master Sprint 0).
