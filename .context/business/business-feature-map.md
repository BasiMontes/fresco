## Scope note — this is a full rewrite, not a patch

The prior version of this map (2026-07-25) was built entirely from PRD/SRS specification, pre-`/project-bootstrap`, with **zero application code** to read — every feature was catalogued `Planned`. That is no longer true anywhere. The app is live: 5 deployed Supabase Edge Functions, ~40 frontend routes/components, 7 real Postgres tables with real rows (1000 recipes, 55 profiles, 53 meal plans), and ~20 shipped bug-fix tickets (FRESCO-89 through FRESCO-119) layered on top of the original MVP scope. This pass re-derived the entire catalog from the running codebase — routes, components, Edge Functions, DB schema (via Supabase MCP), and git history — not from the old spec docs. Where this map disagrees with the PRD/SRS, the code is ground truth.

**The single biggest architectural finding this pass**: Gemini (Google's LLM) has been **fully removed from the production system**. The original design (and the prior version of this map) had Gemini doing three jobs — picking the 21 weekly menu recipes, classifying shopping-list items into aisles, and writing the Pro-tier learning-explanation text. All three were replaced with deterministic in-process algorithms across two commits on 2026-08-01 (`c5dd2fc` / ADR-0005, then `ae3b560` "kill remaining Gemini calls"). **Fresco today has zero external AI API dependency in production.** See §8, gap 1 for a stale-copy consequence of this change still live in the app.

## 8. Discovery Gaps

1. **Stale FAQ copy contradicts the app's own architecture, written 3 days after Gemini was fully removed.** `components/profile/ayuda-section.tsx`'s FAQ answer to "¿Cómo genera Fresco mi menú semanal?" says: *"Gemini solo entra en juego en Plan Pro, para redactar la explicación de qué ha aprendido de ti."* That was true when `/qa/page.tsx` was last updated (2026-08-01, 20:36) but the very same day at 20:14 commit `ae3b560` ("kill remaining Gemini calls") removed that last Gemini call too — and the FAQ component itself was written 3 days *after* that removal (`a277634`, 2026-08-04). The app now makes a factual claim about itself that hasn't been true since before the copy was written. **Ask/fix**: update `FAQ_ITEMS` in `components/profile/ayuda-section.tsx` — the explanation text is 100% deterministic now, not "Gemini writes it."
2. **`recipes` has no DELETE path anywhere** — same gap the pre-code map flagged, still unresolved now that the table holds 1000 real, seeded rows instead of 35. No RPC, no Edge Function, no admin tooling visible in this repo. **Ask**: the founder — is a bad/duplicate recipe removed via direct `service_role` SQL outside this codebase, or is this a real gap?
3. **`recetas_propias` (personal recipes) has no UPDATE or DELETE path.** `components/recipes/recipe-detail.tsx:133` explicitly documents this as "OOS (no edit/delete/rate/menu-add/share)" — a deliberate scope cut, not an oversight, but worth flagging since a user who mistypes a personal recipe currently has no way to fix or remove it short of deleting her entire account (FEAT-011 cascades it away).
4. **No `production` environment defined in `.agents/project.yaml`** — `local` and `staging` both point at the same Supabase project ref (`jdqemhewjrjuopssdurn`); `lib/urls.ts` deliberately throws if `VERCEL_ENV=production` is ever detected, rather than guessing a URL. Carried forward from the prior version of this map — still true.
5. **`worktree-agent-*` branch present but not inspected.** A parallel agent session's worktree branch exists in `git branch -a` (`worktree-agent-a3a9c429d7fa063a6`) — this map didn't check out or diff it, so any in-flight work there isn't reflected here. **Ask**: check whether that branch has unmerged feature work relevant to a future re-run of this map.
6. **Pro self-serve upgrade is a disabled button with no real flow behind it** (FEAT-048) — by design (concierge process, per `mvp-scope.md`), but worth keeping visible here since it's the one clearly-labeled "Próximamente" surface a user can actually see in production today.
7. **`meal_plan_recipes` and `shopping_lists` have no standalone DELETE** — both only disappear via their parent `meal_plans` row's cascade delete (FEAT-021). This is consistent with the data model (a slot or a list without a parent plan is meaningless) rather than a gap, but is worth naming explicitly since the CRUD matrix's ❌ cells could otherwise read as an oversight.
8. **Notifications (FEAT-051) is fully placeholder** — confirmed deliberate (the mockup's pantry-expiration framing doesn't match any real Fresco feature), but it does occupy a real nav slot (bell icon, `/notifications` route) that currently does nothing. Track as a genuine backlog item, not a defect.
