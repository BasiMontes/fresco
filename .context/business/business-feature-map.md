**Architecture invariants carried forward** (all still true): zero external LLM in production (`ADR-0005` — Gemini fully removed 2026-08-01); the Stripe webhook is the *only* writer of subscription state, DB-enforced by a `BEFORE UPDATE` trigger (`ADR-0007`); authorization is row-ownership via `auth.uid()`, never a role column, and an anonymous guest JWT is a first-class `Authenticated` principal (`ADR-0003`); `pg_cron` + `pg_net` is the single scheduler (`ADR-0011`). Where this map disagrees with PRD/SRS, code wins.

## 8. Discovery Gaps

> MANDATORY. Each gap is actionable.

1. **Stale FAQ copy still names Gemini.** `components/profile/ayuda-section.tsx`'s FAQ answer to "¿Cómo genera Fresco mi menú semanal?" claims Gemini writes the Pro learning explanation. That has been false since `ae3b560` (2026-08-01) — `buildLearningExplanation()` is a deterministic template. **Fix**: update `FAQ_ITEMS`. Carried from the 2026-08-07 map, still open.
2. **`generate-shopping-list` has no rate limiting.** `generate-meal-plan` got its 5 req/user/hour limit (FEAT-028, `ADR-0010`). `generate-shopping-list` is the obvious next adopter of the same RPC (SRS `NFR-SEC-6`) — not wired. **Ask**: is it worth it at concierge scale, or wait for real abuse?
3. **`recipes` DELETE is admin-only and untested end-to-end.** FEAT-082 (`delete-catalog-recipe`) is deployed with `ADMIN_USER_ID` set, but the full `/admin/recipes` flow wants an in-app test with a real admin session. A referenced recipe correctly returns `409`. **Ask**: is a bad/duplicate recipe still sometimes removed via direct `service_role` SQL outside this codebase?
4. **No live UI issues `estado = 'sustituida'`.** `update-recipe-status` accepts it with `nueva_recipe_id`, the enum value exists, the trigger no-ops on it — but the calendar uses drag-swap (FEAT-030) and no component was found issuing the `sustituida` call. Possibly dead or planned. **Grep next**: `sustituida` across `components/`.
5. **0 Pro/Family subscribers in the production DB.** The entire Subscription & Billing domain (FEAT-059…063), the Pro generation fork (FEAT-022/023/039/040), the payment-failed notice, and `get_user_recipe_engagement` are unexercised against real subscription data.
6. **One Supabase project for all three environments** (`jdqemhewjrjuopssdurn`). `local`, `staging`, `production` share the ref — a staging API call mutates production rows. The ~47 `auth.users` / 38 profiles are a test/production mix. Deliberate (`master-implementation-plan.md` §3), but every gap downstream of it compounds.
7. **`send-weekly-reengagement-push` depends on a manually-created Vault secret** (`edge_function_secret_key`, `sb_secret_...`). `cron.job` shows the schedule + `apikey` header wired; the secret's presence in `vault.decrypted_secrets` was not verifiable this pass. If absent, the job runs weekly and every send silently `401`s.
8. **`CRON_SECRET` presence not verified.** FEAT-063's reconciliation route returns `500` if `CRON_SECRET` is unset in the target environment; the migration reads it from Vault. Not checked this pass. **Ask**: confirm it's set in the Vercel Production scope + Vault.
9. **Motion epic is partial.** FEAT-066…070 shipped; FRESCO-245 (page transitions) + FRESCO-246 (list/card entry-exit) are still in QA and not in `app/globals.css`. Track as a genuine backlog item, not a defect — the epic's "Definition of Done" checklist is unmet (`epic.md`).

A `/project-foundation` concern — FRESCO-302 tracks the Gemini de-scope. `.context/SRS/non-functional-requirements.md` §7 (Observability) is current.
